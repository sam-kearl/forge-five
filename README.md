# Forge Five

*Five numbers. One target. Forge the answer.*

Forge Five is an arithmetic puzzle game for iOS (first), Android and, later, the web. Each puzzle deals five numbered pieces (1–25) and a target (1–25). You build an equation that uses every piece exactly once with `+ − × ÷` and brackets. You can write it all at once, or **forge** part of it into a new piece that remembers what it's made of.

> "Forge Five" is a working name. Trademark clearance has not been done. See [docs/REVIEW_ITEMS.md](docs/REVIEW_ITEMS.md).

## About this project

**Play the web demo:** _link coming soon_ (works on phones and computers; nothing to install)

Forge Five is a cross-platform (iOS, Android, web) puzzle game built with React Native, Expo and TypeScript. Highlights worth a look:

- **A platform-independent game engine** ([src/engine](src/engine)) with exact rational arithmetic, an expression parser, and pieces that remember what they were forged from.
- **An exhaustive solver** that guarantees every puzzle is solvable. It is cross-checked in tests against an independent brute-force solver.
- **A seeded puzzle generator** with quality scoring, rejection logging and fallbacks. Every puzzle is reproducible from its id.
- **About 430 automated tests**, including a randomized test that checks the piece invariant after every one of thousands of moves.
- **Accessibility built in:** screen-reader labels (duplicate numbers stay distinguishable), tap-only play, reduced motion and keyboard play on the web.
- **Original design and assets:** artwork, icons and sound effects are all generated by code in this repo.
- **Written design records** in [docs/](docs), covering decisions, privacy inventory, licences and a release checklist.

The demo runs entirely in the browser with no accounts and no tracking. Ads and purchases are simulated; no real ad or payment service is connected.

## Quick start

Requirements: Node 22 LTS. For iOS you also need Xcode (with a simulator runtime) and CocoaPods. For Android you need Android Studio and JDK 17.

```bash
npm install
npm test               # all unit and component tests
npm run typecheck
npx expo start --web   # quickest way to play (Expo web)
```

### Native development builds

Forge Five uses an **Expo development build**, not Expo Go:

```bash
npx expo run:ios       # builds ios/ via prebuild, installs on a simulator, starts Metro
npx expo run:android   # same for Android
```

> **Known limitation: folder paths with spaces.** Expo's iOS build phase for `expo-constants` fails when the project path contains spaces (xcodebuild exit 65 at "Generate app.config for prebuilt Constants.manifest"). Keep the project in a path without spaces, e.g. `~/dev/forge-five`. Metro and the web build are unaffected.

> **iOS 27 SDK and the scene life cycle.** Apps built with Xcode 27 must adopt `UIScene`, or they refuse to launch. Expo SDK 57's runtime supports this, but its native template doesn't use it yet. The local config plugin [`plugins/withIOSSceneLifecycle.js`](plugins/withIOSSceneLifecycle.js) adds the SceneDelegate, the Info.plist scene manifest and the AppDelegate change. It is a no-op once the template includes them (SDK 58), so it can be removed after upgrading.

After the first build, `npx expo start` is enough for JavaScript-only changes. Native folders (`ios/`, `android/`) are generated by Continuous Native Generation and are git-ignored. Configure native behaviour only through `app.json` and config plugins.

To show the placeholder ad frame during development, set `EXPO_PUBLIC_ADS=mock`.

## Project structure

```
src/
  app/            Expo Router screens: index (home), play, tutorial, stats, settings, parents, privacy, about
  engine/         Pure TypeScript game engine. No React, React Native, Expo or services (enforced by a test).
    rational.ts     exact numbers              config.ts     the one place ranges, rules and tuning live
    arithmetic.ts   rule-checked operations    expr.ts       expression trees
    parse.ts        workbench tokens → tree    format.ts     tree → text with safe parentheses
    text.ts         typed text → tokens (no free constants)
    pieces.ts       source/forged pieces and provenance
    validate.ts     full solution validation   solver.ts     exhaustive solver
    canonical.ts    solution normal form       quality.ts    puzzle quality metrics
    generator.ts    verified puzzle generator  rng.ts        seeded PRNG
    game.ts         game state + reducer (every player move, undo/redo)
  features/       game board, tutorial, parental gate, ad slot
  services/       storage, ads, purchases, sound, haptics (interfaces + implementations)
  state/          app context and pure settings/stats models
  ui/             design tokens and reusable components (pieces, blueprint, seal, icons)
scripts/          puzzle report, sound synthesis
docs/             plan, design system, licenses, privacy, review items, release checklist, web readiness
assets/sounds/    original synthesised WAV files
```

## How the engine guarantees solvable puzzles

1. The generator picks five numbers from an original weighted distribution. It either builds a random legal expression tree from them (**constructive**), or picks a target the solver says is reachable (**validated random**).
2. The **exhaustive solver**, a dynamic program over subsets of piece identities, independently confirms a solution exists. Its correctness is cross-checked in tests against a separate brute-force solver on hundreds of random puzzles.
3. A **quality filter** rejects trivial, tedious or near-duplicate puzzles. Each rejection reason is counted.
4. Attempt budgets, progressively relaxed thresholds and a list of hand-verified fallback puzzles mean generation always ends.
5. Everything is deterministic from a 32-bit seed. The puzzle id (`F5-…`) encodes it.

See [docs/PLAN.md](docs/PLAN.md) for the full design record.

## Testing

`npm test` runs roughly 430 tests covering:

- arithmetic, parsing, precedence and formatting;
- piece identity and provenance, and a randomized test that checks the piece invariant after every one of thousands of moves;
- the solver against a brute-force reference;
- generator ranges, determinism, safeguards and quality rules;
- the reducer (forge, undo/redo, clear, break apart, check);
- the tutorial script, parental gate, statistics, persistence, ad policy and purchase flows;
- rendered accessibility labels and tap-only play.

The manual verification checklist is in [docs/RELEASE_CHECKLIST.md](docs/RELEASE_CHECKLIST.md).

## Releasing

The web demo deploys to Vercel from the `main` branch using [vercel.json](vercel.json).

Mobile releases are built with EAS (`npx eas-cli@latest build`, `submit`). Before the first release, work through [docs/RELEASE_CHECKLIST.md](docs/RELEASE_CHECKLIST.md) and [docs/REVIEW_ITEMS.md](docs/REVIEW_ITEMS.md). Placeholder identifiers such as `com.example.forgefive` in `app.json` must be replaced.
